# Kourosh UI Foundation — Phase 3 / v271

## Scope

Phase 3 establishes the canonical validation, responsive form-grid, and RTL/BiDi contracts. It intentionally does not migrate every form; full application migration is Phase 4.

## Canonical owners

- `components/ui/formValidation.ts` — Persian validation messages and common validators.
- `components/ui/FormGrid.tsx` — responsive form composition using the project's reserved breakpoints.
- `components/ui/BidiText.tsx` — semantic `<bdi>` isolation for phone/IMEI/code/email/URL/number/currency values.
- `components/ui/TextField.tsx` — semantic `valueKind` contract and separation of RTL field-shell direction from LTR control content.
- `components/FormErrorSummary.tsx` — semantic-token validation summary and focus navigation.

## Repair intake pilot

`pages/AddRepair.tsx` is the Phase 3 pilot form:

- required-field messages are generated by the centralized validation contract;
- invalid submit focuses the first invalid field;
- a form-level error summary links to each invalid field;
- field-local errors continue to render directly below their owning field through `ControlShell`;
- customer/device/issue field groups use `FormGrid` instead of page-owned grid templates;
- phone and IMEI values use semantic BiDi isolation;
- customer-mobile, IMEI, and currency inputs use `TextField.valueKind` for LTR content without flipping Persian labels.

## Accessibility behavior

- form remains `noValidate`, so browser-native English validation bubbles do not replace Persian errors;
- required fields expose `aria-required`;
- invalid controls expose `aria-invalid` and `aria-describedby` through canonical primitives;
- field errors remain live/polite feedback;
- summary items can focus/scroll the exact field;
- mixed RTL/LTR display values use `<bdi>` isolation.

## CSS / architecture discipline

- no new CSS file was introduced;
- no page-specific validation CSS was introduced;
- no arbitrary breakpoint or arbitrary form grid was added;
- `FormErrorSummary` no longer owns hard-coded red/slate palette utilities and now uses semantic tokens;
- business logic, APIs, DB schema, and payload contracts are unchanged.
